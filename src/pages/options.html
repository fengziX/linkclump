常见问题


  • 本地页面（file:// 地址）怎么用？ 打开扩展管理页（chrome://extensions），给 Linkclump 勾选「允许访问文件网址」。
  • 打开了两份标签？ 检查是否装了功能相似的扩展。若同时装了 Snap Links Lite，看起来像是 Linkclump 在工作，实际上它也会在后台开标签。
  • 必须设置按键吗？ 在 Linux / Mac 上想用右键就必须指定一个按键，这是 Chrome 的设计限制；左键和中键不受影响。
  • 完全没反应？ 确认鼠标键与组合键设置正确。另外出于安全考虑，Chrome 会在网上应用店和扩展管理页面自动禁用扩展。
  • 框选时页面文字被选中？ 本版本已改用标准的 user-select 禁用方式，若仍有异常请反馈具体站点。
  • 缩放页面后滚动不流畅？ 浏览器缩放较小时自动滚动会有顿挫感，属于已知限制。
  • 源码在哪里？ 见 GitHub 仓库，欢迎提交改进。

已访问链接标记（Chrome 136+ 兼容）

Chrome 136 起对 :visited 历史做分区隔离，150 起彻底强制：扩展从后台打开的链接不会被原网页记为「已访问」，所以标题文字不会变色。本功能由扩展自己记录已打开的网址并给链接染色，效果与旧版一致。

为避免与 Bilibili-Evolved 等重度脚本互相放大，默认只标记当前视口附近的链接（最多 80 个、分批进行），iframe 内不自动标记，也不监听页面变动；滚动到新区域或刷新后，当前屏幕内的链接仍会重新染色。

默认 #551A8B（深紫，浅色背景上清晰）。可填任意深色，如 #C00000 深红、#00695C 深青；留空即恢复默认深紫。

默认关闭。勾选后忽略上面的颜色，直接读取站点自己的 a:visited 色；很多站点把它设成很淡的灰，会看不清。

默认关闭。开启后会监听页面 DOM 并给新出现的链接染色；与 Bilibili-Evolved 等脚本同时使用时可能导致页面卡顿，B 站建议保持关闭。
